# PoC 개인정보 마스킹 정책 후보

이 폴더의 파일은 PoC 화면에 여러 복잡한 옵션을 노출하기 위한 것이 아니라, 내부 비교 후 서버 기본 정책을 정하기 위한 후보입니다.

## 공통 범위

- 공식 평가 대상: 주민등록번호, 외국인등록번호, 여권번호, 운전면허번호
- 추가 시연 대상: 전화번호, 이메일
- 여섯 유형은 모두 규칙 기반 탐지기로 처리하므로 `execution_mode`는 `rule_only`로 둡니다.
- PoC 화면에서 공식 평가만 실행할 때는 `selected_categories`를 고유식별정보 4종으로 제한합니다.
- 전화번호·이메일 추가 기능을 켜면 두 유형을 `selected_categories`에 추가합니다.
- AEGIS는 이름·주소 등 문맥형 개인정보를 추가 시연할 때 별도 정책으로 켭니다. 현재 세 정책에서는 실행하지 않습니다.

## 후보 비교

| 파일 | 목적 | 패턴 처리 | 체크섬 | 문맥 없는 후보 | 검수 후보 | 권장 용도 |
|---|---|---|---|---|---|---|
| `00_poc_official_core.json` | 공식 평가 4종 기본 실행 | 숫자 주변 OCR 혼동문자까지 제한 복구 | 사용하지 않음 | 허용 | 마스킹 | 공식 PoC 기본 |
| `01_precise_comparison.json` | 오탐 최소 비교 | OCR 원형에 가까운 문자열 | 사용, 실패 시 제외 | 제외 | 제외 | 내부 비교용 |
| `02_balanced_comparison.json` | 중간 기준 비교 | 공백·번호 조각·중복 구분자 정리 | 사용하되 실패 후보도 마스킹 | 허용 | 마스킹 | 내부 비교용 |
| `03_poc_default_recall.json` | 4종과 전화번호·이메일 추가 시연 | 숫자 주변 OCR 혼동문자까지 제한 복구 | 사용하지 않음 | 허용 | 마스킹 | 추가 기능 시연 |

## 권장 운영 방식

PoC 사이트의 서버 기본값은 `00_poc_official_core.json`을 사용합니다. 전화번호·이메일 property를 켠 추가 기능 시연에는 `03_poc_default_recall.json`을 사용하거나, 요청 시 `selected_categories`에 두 유형만 추가합니다.

체크섬은 PoC 기본값을 `false`로 둡니다. 샘플 문서에는 합성 번호나 OCR 오인식 번호가 포함될 수 있기 때문에 체크섬을 필수로 하면 형식상 가려야 할 번호가 누락될 수 있습니다. 단, 결과 보고서에는 체크섬을 끈 상태였다는 점과 오탐 가능성을 명시해야 합니다.

`02_balanced_comparison.json`과 `03_poc_default_recall.json`의 결과가 같다면 더 단순한 `02`를 선택합니다. `03`에서만 추가로 찾은 후보가 실제 개인정보인 경우 `03`을 유지합니다. `03`에서 일반 영문·숫자 문자열까지 잘못 가리는 사례가 늘면 `02`로 낮춥니다.

## 현재 테스트 문서 비교 결과

`sample_data/test_docs_ocr_results.json`의 32개 문서를 각 정책으로 한 번씩 실행한 결과입니다. 이 수치는 정답 데이터와 비교한 정확도가 아니라 최종 후보 수이므로, 많다고 반드시 좋은 것은 아닙니다.

| 정책 | 최종 후보 | 개인정보가 나온 문서 | 유형별 후보 |
|---|---:|---:|---|
| 정확성형 | 22건 | 9건 | 주민등록번호 4, 전화번호 18 |
| 균형형 | 30건 | 12건 | 주민등록번호 5, 전화번호 18, 이메일 7 |
| 누락 최소형 | 33건 | 15건 | 주민등록번호 6, 외국인등록번호 2, 전화번호 18, 이메일 7 |

누락 최소형에서만 추가된 번호는 다음 세 건입니다.

- `541101-4956085`: 주민등록번호 형태, 체크섬 검사를 생략하여 보존
- `519101-8120783`: 외국인등록번호 형태, 날짜·체크섬이 유효하지 않아 실제 개인정보 여부 확인 필요
- `401932-7606955`: 외국인등록번호 형태, 날짜·체크섬이 유효하지 않아 실제 개인정보 여부 확인 필요

PoC 샘플이 합성번호를 사용하고 `6자리-7자리` 모양을 가리는 것을 기대한다면 누락 최소형이 적합합니다. 반대로 실제 운영 문서에서 날짜와 체크섬이 틀린 번호 모양의 문자열을 오탐으로 보아야 한다면 균형형이 더 안전합니다.

## 화면과 JSON의 연결

PoC 화면에서 사용자가 조정할 값은 최소한으로 둡니다.

- 고유식별정보 4종: 기본 선택
- 전화번호·이메일: 추가 기능 선택
- 체크섬 검사: 기본 해제, 비교가 필요할 때만 선택

화면에서 바꾸지 않을 내부 고정값은 `execution_mode`, `merge_mode`, `minimum_risk_level`, 문맥 Gate, AEGIS threshold, 인접 줄 수입니다. 이 값들은 테스트 결과를 보고 서버 정책 파일에서만 변경합니다.
